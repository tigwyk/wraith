# Wraith M3 Implementation Plan: Workspaces, Tabs, Splits, Chrome, Inline Images

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One window shows a workspace of tabs, each a tree of split panes, with sidebar, command palette, workspace picker, profiles, shell integration, a custom title bar and Kitty inline images. The server owns the layout and restores it after a restart.

**Architecture:** The pure model (ids, pane tree, snapshot) lives in `wraith-proto`. The server wraps it in a state machine (`Model::apply(ModelCmd) -> Vec<Effect>`) that never touches a process, so every layout rule is unit-tested without ConPTY. The session maps effects to pane threads, pushes a whole `ModelSnapshot` to the window that has the workspace attached, and forwards events only for panes that window subscribed to. The client mirrors the snapshot, computes pane rectangles from the tree, and draws chrome and panes through one quad pipeline in one submit per frame.

**Tech Stack:** Rust stable (MSVC), Zig 0.15.2 (`.tools/`), `windows` 0.62, `postcard`, `serde_json` (layout file only), `png` 0.18 (Kitty PNG decode), `crossbeam-channel`, `tracing`.

**Spec:** `docs/superpowers/specs/2026-11-01-wraith-terminal-design.md` (§3.4 IPC, §3.5 shell integration, §4 data model and UI, §6.1 inline images, §6.3 always fast, §7 config, §8 errors, §10 M3). Builds on `docs/superpowers/plans/2026-11-01-wraith-m2.md`.

## Global Constraints

- Branch `m3` from `main`. Ledger `docs/m3-ledger.md`. Test commands run as `rtk proxy cargo test ...` and success is read from the exit code, never grepped from RTK-indented output.
- `PROTO_VERSION` becomes **2**. Pipe name, DACL, handshake, 64 MiB frame cap, one unacked `FrameDelta` per pane, input-before-output and p99 < 3 ms input round trip are unchanged from M2.
- **A pane is never resized below 2×1 cells.** Hidden panes keep their last size (spec §4.1).
- A workspace is attached to at most one window; attaching it elsewhere moves it (spec §4.1).
- Closing the last pane closes the tab; the last tab closes the workspace; closing the last workspace leaves one empty default workspace and the window stays open. After a close, focus goes to the neighbor in visual order.
- New tabs start in the workspace `root_dir`, else the focused pane's cwd, else `%USERPROFILE%`.
- `layout.json` at `%LOCALAPPDATA%\wraith\layout.json` (env `WRAITH_LAYOUT_PATH` overrides, tests use it), written on every model change debounced **1 s**, atomic replace, restored with **fresh shells** at server start (spec §4.4).
- Window X detaches (shells keep running). `close_surface` (`ctrl+shift+w`) closes the focused pane and kills its shell, asking first if it is still running (M2 user decision, now per pane).
- New window with no workspace requested: attach the most recently detached workspace, else create "Workspace N" (M2 user decision, now per workspace).
- Default keybinds (Windows Terminal conventions, spec §7): `ctrl+shift+t` new_tab, `ctrl+tab` next_tab, `ctrl+shift+tab` previous_tab, `alt+shift+plus` new_split:right, `alt+shift+minus` new_split:down, `alt+left|right|up|down` goto_split, `ctrl+shift+b` toggle_sidebar, `ctrl+shift+p` command_palette, `ctrl+shift+o` workspace_picker, `ctrl+shift+n` new_window. Ghostty action names are kept where Ghostty has one (`new_tab`, `close_tab`, `next_tab`, `previous_tab`, `goto_tab:N`, `new_split:right|down|left|up`, `goto_split:previous|next|left|right|up|down`, `toggle_split_zoom`, `resize_split:dir,N`, `equalize_splits`).
- Image memory per pane is capped by `image-storage-limit` (default 320 MB). Sixel and iTerm2 images are not supported (spec §6.1).
- Chrome text uses the terminal font and cell metrics.

## Scope rulings (decided here, so execution does not stall)

- **Snapshot, not event stream.** The server sends the whole `ModelSnapshot` after each change (it is a few KB). Spec §3.4's per-change `ModelEvent`s are replaced; cost if wrong: more bytes per change.
- **Square chrome.** The spec's rounded-rect pass is skipped (`shortcut: square corners, add an SDF kind when chrome gets a design pass`).
- **OSC 133 is emitted by the integration scripts but not consumed in M3.** M3 consumes OSC 7 (cwd) only, through libghostty's `pwd()`. Prompt jumping and "select command output" move to the M5 backlog; "process ended" detection is M4's.
- **The sidebar has no AGENTS section** until M4 has agent state to show.
- **zsh and WSL integration** inject through `ZDOTDIR` and `--rcfile`; they are covered by command-line builder unit tests plus a manual check, not an automated shell run.
- **Kitty image ids are per pane** (each terminal has its own id space), so the client keys textures by `(PaneId, image_id)`.
- **Workspace `layout` (third field of `workspace = name:dir[:layout]`)** is one of `single` (default), `cols` (two side by side), `rows` (two stacked), `grid` (2×2).

## Review Focus

1. **Corrupt, truncated, empty or future-version `layout.json`:** the server must start with one empty default workspace, move the bad file to `layout.json.bad`, and never crash. Task 4 `bad_layout_file_is_quarantined`.
2. **A pane exits while its tab is hidden or its workspace is detached:** it stays in the tree showing its exit code (not silently removed, not a restart loop). Task 3 `exit_keeps_pane_in_tree`, Task 4 `exited_pane_survives_detach`.
3. **Two windows fight for one workspace:** the second attach steals it, the first receives `WorkspaceTaken` and stays alive. Task 4 `second_window_steals_workspace`.
4. **Tiny window with many splits:** layout never yields a pane below 2×1 and never panics on a zero-size area. Task 1 `layout_never_below_min`, `layout_zero_area_is_empty`.
5. **Oversize or vanished images:** an image whose RGBA data cannot fit one frame is skipped with a log, a deleted image sends `ImageDelete`, a placement scrolled half above the viewport keeps a negative row. Task 12 `oversize_image_is_skipped`, `deleted_image_sends_delete`, Task 13 `partly_scrolled_image_is_clipped`.

**Interfaces:**
- Consumes: Task 3 `Model`/`Effect`, `ModelCmd`.
- Produces: `PROTO_VERSION = 2`.
  `ClientMsg { Hello{proto_version, kind}, AttachWindow { workspace: Option<WorkspaceId> }, DetachWindow, Model(ModelCmd), Subscribe { panes: Vec<PaneId> }, Cmd { pane, cmd }, Kill { pane }, List, ServerStop }`
  `ServerMsg { Welcome, VersionMismatch, WindowAttached { workspace: WorkspaceId }, Snapshot(ModelSnapshot), WorkspaceTaken { workspace }, Event { pane, ev }, Panes(Vec<PaneInfo>), Error(String) }`
  `PaneInfo` gains `workspace: WorkspaceId`. `PaneEvent` gains `Cwd(String)`.
  `fn run_server(pipe: &str)` and `spawn_server_thread` read `WRAITH_LAYOUT_PATH` (else the default path) once.
  Session rules: `AttachWindow{None}` attaches `most_recent_detached`, else the model's empty/default workspace is used if detached, else a new empty workspace; the reply is `WindowAttached` then `Snapshot`. `AttachWindow{Some(id)}` on a workspace held by another client moves it and sends the old holder `WorkspaceTaken`. A GUI client may `Cmd`/`Subscribe` only panes of its workspace; `Cli` any pane. `Event` is delivered to a client when the pane is in its `Subscribe` list (Frame, ImageUpload, ImageDelete, MouseTracking, Copied, Clipboard, PasteNeedsConfirm, InputWritten) or in its workspace (Title, Bell, Exited, Cwd). Subscribing a pane sends it `Reattach` (full redraw, fresh unacked state). `Model` commands from a GUI client apply to its workspace's objects only; effects spawn or drop pane threads; every change pushes `Snapshot` to the workspace's holder. Title, cwd and exit events call `note_*` and push a snapshot. `Kill{pane}` is `ClosePane`. Dropping/`DetachWindow` marks the workspace detached; exited panes stay (Task 3).
  Persistence: after any model change schedule a save 1 s later (coalesced; saved on `ServerStop` before panes are dropped; `ServerStop` never deletes the file); write temp file then `MoveFileEx(REPLACE_EXISTING)`. At start: load; on parse/IO error move the file to `layout.json.bad`, log, start with `Model::new()`; spawn `restore_effects` panes. Panes spawn with env `WRAITH_PANE_ID`, `WRAITH_PIPE`, `TERM_PROGRAM=wraith` added.
