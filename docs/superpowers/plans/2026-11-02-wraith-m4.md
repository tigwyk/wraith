# Wraith M4 — Agent Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A coding agent (Claude Code, Codex, others) that needs the user while its pane is hidden or the window is in the background shows on screen within 1 s: a state badge on its tab, a row in the sidebar's Agents list, a taskbar flash and badge, and a Windows toast. Clicking the toast focuses the pane.

**Architecture:** A new pure `agent` crate holds the harness table, the event and state types, the `step` state engine and text sanitising. The server keeps one `Tracker` per pane, fed by three sources:
- hook events from `wr hook` (a new `Hook` client kind);
- terminal signals from libghostty callbacks: OSC 9/777 notifications, OSC 9;4 progress, OSC 7501 program status, BEL, title and OSC 133;D;
- a 1 Hz process scan of the pane's Job Object.

Agent state rides in `PaneMeta` inside the model snapshot. When attention rises, the server sends `Notify` to exactly one window. That window shows the toast, flash and badge, and focuses the pane when the toast is clicked.

**Tech Stack:** Rust, `windows` 0.62 (WinRT `UI_Notifications` and `Data_Xml_Dom`, `Win32_UI_Shell` for `ITaskbarList3`, the `IShellLinkW` shortcut and `SetCurrentProcessExplicitAppUserModelID`). `regex` for the harness matchers and `agent-detect`. The `serde_json` already in use for the Claude settings file.

**Spec:** `docs/superpowers/specs/2026-11-01-wraith-terminal-design.md` §5 (Agent integration), §4.2 (sidebar, tab bar), §7 (config), §10 (M4 row)

## Global Constraints

- **Hook command:** `wr hook <harness> [event]` exits 0 within 200 ms whatever happens. It never prints to stdout and caps the payload at 64 KiB. With `WRAITH_PANE_ID` or `WRAITH_PIPE` missing it exits 0 at once.
- **Hook client permissions:** a `Hook` client may send only `AgentEvent`, and only for an existing pane id.
- **Untrusted text:** hook and OSC text is untrusted. Strip control characters and trim it to 200 characters before showing it. Never interpret it as markup.
- **Default to Idle:** unknown or ambiguous input → Idle.
- **Ask latch:** `Waiting(Ask)` latches until the user types in that pane. Focusing or viewing the pane does not clear it.
- **TurnEnd attention:** `Waiting(TurnEnd)` raises attention only if the pane was hidden when the turn ended, and clears when the pane becomes visible.
- **Hooks beat passive signals:** after a hook event, passive state signals for that pane are ignored for 10 minutes. Passive icon detection still runs.
- **Installers:** they never write without confirmation, always keep a `.bak`, and are idempotent. Tagged entries are replaced, and uninstall removes only those.
- **Notification config:** `agent-notify = toast,flash,badge,sound` (any subset), `agent-notify-when = unfocused|always`, `agent-notify-quiet = HH:MM-HH:MM`.
- **Detection config:** `agent-detect = <name>:<regex>` extends the process matchers.
- **Toast:** title `"<Agent> needs input — <workspace>/<tab>"`, body = message. AUMID `Wraith.Terminal`, via a Start Menu shortcut created on first run.
- **Speed:** within 1 s of an agent asking, for a hidden pane or a background window.

## Scope rulings (made at planning, ledgered)

- **No sidecar OSC parser:** the vendored Ghostty now exposes `on_desktop_notification`, `on_progress_report`, `on_program_status` (OSC 7501) and `on_semantic_prompt`. Spec risk 3 is retired.
- **OSC 7501 program status:** a passive signal, mapped as
  - `working` → Working;
  - `blocked` → Ask (with its message);
  - `done` → TurnEnd;
  - `idle`, `error`, `clear` → Idle.

  It is the most precise passive source the terminal offers, so it is worth taking.
- **Toast activation:** handled in the window process through the toast's `Activated` event, which focuses the pane. The spec's `wraith.exe --activate pane:<id>` COM activation is not built. Clicking a toast after its window closed only opens Wraith, which reattaches. *Cost: such a click cannot pick the pane.*
- **No `agent-tab-pulse`:** the key is not added (the spec says optional). The badge is enough to see.
- **WSL:** `WRAITH_PIPE` joins `WSLENV`, so `wr.exe` called from a WSL hook reaches the server. `wr install-hooks claude --wsl <distro>` edits that distro's `~/.claude/settings.json` through `wslpath`. Process scanning cannot see processes inside WSL, so detection there relies on hooks and terminal signals.
- **Codex:** not installed on this machine. Its path is tested with the documented `notify` payload, not a live Codex.

## Review Focus

1. **Hook spam or a crashed agent:** a pane flooded with hook events must not freeze input or the UI. Snapshot pushes for agent changes are coalesced to one per 100 ms per server.
2. **A malicious or broken hook client:** an `AgentEvent` for another user's pane id, a nonexistent pane, or a non-hook message from a `Hook` client is ignored. The connection is never trusted with anything else.
3. **The agent exits mid-Ask (Ctrl+C, crash):** process-scan Detached and OSC 133;D clear the state. A stale "needs input" must not stay forever.
4. **The window is closed while an agent waits:** with no window attached, `Notify` goes to the last focused window. With no windows at all, nothing breaks, and the state is there when a window attaches.
5. **Unreadable or odd settings files** (`settings.json` invalid JSON, `config.toml` with tables): the installer refuses, without writing, and says why.

### Task 1: `agent` crate — harnesses, events, state engine, sanitising

**Files:** create `crates/agent/{Cargo.toml,src/lib.rs,src/harness.rs,src/state.rs,tests/state.rs,tests/harness.rs}`; root `Cargo.toml` (member + workspace dep).

**Interfaces (produces):**
- `pub enum Signal { Attached { harness: String }, Detached, Working, Ask { message: String }, TurnEnd { message: String }, Idle }`
- `pub enum Source { Hook, Passive }`
- `pub enum State { Idle, Working, Waiting(Wait) }`, `pub enum Wait { Ask, TurnEnd }`
- `pub struct Agent { harness: String, state: State, attention: bool, message: String, last_hook: Option<Instant> }`
- `pub struct Ctx { visible: bool, now: Instant }`
- `pub fn step(a: Option<Agent>, sig: &Signal, src: Source, ctx: &Ctx) -> Option<Agent>`
- `pub fn typed(a: &mut Agent)`: user input clears the Ask latch.
- `pub fn became_visible(a: &mut Agent)`: clears TurnEnd attention.
- `pub fn sanitize(s: &str) -> String`
- `pub struct Harness { id, name, icon: char, exe: &[&str], cmdline: Option<Regex>, ask_title: Option<Regex> }`
- `pub fn harnesses() -> &'static [Harness]`
- `pub fn match_process(exe: &str, cmdline: &str, extra: &[(String, Regex)]) -> Option<String>`

- `unknown_or_empty_message_defaults_idle`

### Task 2: Protocol and model: agent info, hook client, notify

**Files:** `crates/proto/src/{wire.rs,model.rs}`, `crates/server/src/{session.rs,model.rs}`, `crates/server/tests/session.rs`.
- `PROTO_VERSION = 3`.
- `ClientKind::Hook`.
- `ClientMsg::AgentEvent { pane, harness: Option<String>, signal: AgentSignal }`, `ClientMsg::Foreground(bool)`.
- `ServerMsg::Notify { pane, title, body }`.
- `PaneMeta.agent: Option<AgentInfo { harness, name, icon, state: AgentState, attention: bool, message }>`.
- `AgentSignal` and `AgentState` mirror the agent crate in proto, with conversions in the server.

**Server behavior:**
- A per-pane `Tracker` steps on hook or passive signals.
- Visibility = some GUI client subscribes to the pane. `Input` (Key/Text/Paste) calls `typed`. Subscribing the pane calls `became_visible`.
- On a rise in attention, send `Notify` to the window holding the workspace, else to the most recently focused GUI window. Apply the pushes are coalesced, per Review Focus 1.

**Tests:** `hook_client_may_only_send_agent_events`, `hook_event_for_unknown_pane_is_ignored`, `ask_in_hidden_pane_notifies_owner_window_once`, `ask_notifies_last_focused_window_when_workspace_detached`, `typing_clears_ask`, `viewing_clears_turn_end_attention`, `agent_info_reaches_snapshot`.

### Task 3: Passive signals in the pane

**Files:** `crates/server/src/{pane.rs,agentscan.rs}`, `crates/proto/src/pane.rs` (`PaneEvent::Agent(AgentSignal)`), `crates/server/tests/pane.rs`.

**Sources:**
- libghostty callbacks into the outbox: desktop notification → Ask(body); progress active → Working; program status, mapped as in the rulings; BEL → Ask(""); OSC 133;D → Detached.
- The title is checked against the attached harness's `ask_title` in the session.
- Process scan every 1 s on the pane thread, only while the job has more than the shell: `job_pids` → image name and command line → `match_process` → Attached/Detached on change.

**Tests:** `osc9_notification_becomes_ask`, `osc7501_states_map`, `bel_becomes_ask_signal`, `process_scan_attaches_and_detaches` (a pane runs `emit-seq`, renamed via the `agent-detect` regex, sleeping).

### Task 4: `wr hook` and the installers

**Files:** `crates/cli/src/{main.rs,hook.rs,install.rs}`, `crates/cli/tests/{hook.rs,install.rs}`.

**`wr hook`:**
- `claude [event]`: reads the stdin JSON `hook_event_name` and `message`. `SessionStart` → Attached, `UserPromptSubmit`/`PreToolUse` → Working, `Notification` → Ask(message), `Stop` → TurnEnd, `SessionEnd` → Detached.
- `codex <json>`: `agent-turn-complete` → TurnEnd(last-assistant-message).
- `generic --state …`.
- A 200 ms overall deadline enforced by a watchdog thread that exits the process.

**`wr install-hooks claude|codex [--wsl <distro>] [--yes]`:**
- Shows a diff, asks y/N, writes a `.bak`, and is idempotent. Entries are tagged by the exact command `"<wr path>" hook claude`.
- `wr uninstall-hooks …`.
- `config.toml` editing is line-based: the top-level `notify = …` is replaced, or inserted before the first table. A `notify` inside a table is refused (Review Focus 5).

**Tests:** `hook_without_env_exits_0_silently`, `hook_sends_agent_event_and_exits_fast` (a server thread receives it), `hook_never_writes_stdout`, `claude_install_is_idempotent_and_backs_up`, `claude_uninstall_removes_only_tagged`, `install_refuses_invalid_json_without_writing`, `codex_install_replaces_top_level_notify_only`.

### Task 5: Client — badges, Agents sidebar, notifications

**Files:** `crates/client/src/{view.rs,app.rs,notify.rs,chrome.rs}`, `crates/client/Cargo.toml` (windows features), `crates/client/tests/view.rs`, `crates/config` (agent keys).

**Drawing:**
- Tab: harness icon before the title. Badge: a spinner for Working, an accent dot for Waiting.
- Sidebar: the workspace attention dot (rolled up: pane → tab → workspace); then "AGENTS" rows sorted Waiting (oldest first) → Working → Idle. A click focuses the pane: attach its workspace, select its tab, focus it.

**Notifications:**
- `ClientMsg::Foreground` on `WM_ACTIVATE`.
- On `Notify`, follow `agent-notify` / `-when` / `-quiet`: a toast through `ToastNotificationManager` with AUMID `Wraith.Terminal` (the shortcut created on first run), `FlashWindowEx` until foreground, and an `ITaskbarList3` overlay badge cleared on foreground. Sound uses the toast's default audio.
- A toast click → `WM_APP+1` with the pane → focus it and bring the window forward.

**Tests (view):** `agents_rows_sorted_waiting_working_idle`, `workspace_attention_rolls_up`, `agent_row_click_focuses_pane_across_workspace`, `notify_policy_respects_when_and_quiet_hours` (pure `fn should_notify(cfg, foreground, visible, now) -> NotifyWays`).
