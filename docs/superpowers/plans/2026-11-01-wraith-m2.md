# Wraith M2 Implementation Plan: Server/Client Split

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Shells live in a background `wraith.exe --server` process. Closing the window keeps them running, and the next launch reattaches to the same shell and screen.

**Architecture:** The M1 pane engine moves behind a per-user named pipe without changing how it works. `PaneCmd`/`PaneEvent` become wire types in `wraith-proto`. A new `wraith-ipc` crate provides a full-duplex framed pipe. The server keeps a registry of panes and routes each pane's events to the one client attached to it. The client swaps `spawn_pane` for `RemotePane::attach`, which has the same `send` / `events` shape, so `app.rs` barely changes. `wr.exe` is a small console CLI over the same pipe.

**Tech Stack:** Rust stable (MSVC), Zig 0.15.2 (`.tools/`), `windows` 0.62 (named pipes, overlapped I/O, security descriptors), `postcard`, `crossbeam-channel`, `tracing`.

**Spec:** `docs/superpowers/specs/2026-11-01-wraith-terminal-design.md` (§3.1 binaries, §3.3 server threading, §3.4 IPC, §4.1 model rules, §6.3 always fast, §8 error handling, §10 M2)

## Global Constraints

- Pipe name `\\.\pipe\wraith-<user-SID>`. Its DACL grants the current user's SID only, with `PIPE_REJECT_REMOTE_CLIENTS`. `WRAITH_PIPE_NAME` overrides the name (tests use unique names so they never touch the user's real server).
- Handshake: `Hello{proto_version, client_kind}` → `Welcome{server_version}` or `VersionMismatch{server_version}`.
- At most one unacknowledged `FrameDelta` per pane (unchanged from M1).
- `libghostty-vt` is used only by `wraith-server` code. The client *binary* links the server lib for `--server` mode, but client *code* never calls libghostty.
- The server keeps running after the last client disconnects. It exits only on `ServerStop` (`wr ctl server-stop`). Shells die with the server, because the Job Objects belong to it.
- **Window close (user decision):** clicking the window's X *detaches* (shell keeps running). `close_surface` (Ctrl+Shift+W) *kills* the shell, asking first if it's still running.
- **New window (user decision):** attach to the most recently detached pane. If there is none, spawn a new pane. A pane is attached to at most one client.
- Client startup: connect, else spawn the server, then retry for **2 s**, else show an error screen with the log path (spec §8).
- Server logs: `%LOCALAPPDATA%\wraith\logs\server.YYYY-MM-DD.log`, 7 kept, level from `WRAITH_LOG`.
- Typing stays fast through the pipe: client send → `InputWritten` round trip **p99 < 3 ms** while the pane floods output (spec §6.3).
- Frames on the wire are capped at **64 MiB**. A larger length prefix drops the connection.

## Review Focus

0. **Typing latency through the pipe** under a flood. Task 3 `remote_input_round_trip_is_fast`.
1. **Client killed mid-frame** (Task Manager, crash): the server must notice, detach the pane, and never block writing to a dead pipe. Task 3 `client_crash_detaches_pane_and_shell_survives`.
2. **Two windows launched at once**, both trying to start a server: exactly one server wins (`FILE_FLAG_FIRST_PIPE_INSTANCE`), the other exits, and both clients end up connected. Task 4 `concurrent_launches_share_one_server`.
3. **Pipe-name squatting** by another process: the client refuses a server whose process is not owned by the current user. Task 2 `client_checks_server_owner`.
4. **Malformed or huge frames:** a length over 64 MiB, or a truncated body, errors without allocating. Task 1 `oversize_frame_is_rejected_before_alloc`, `truncated_frame_errors`.

### Task 2: `wraith-ipc`: secure full-duplex named pipe

**Files:**
- Create: `crates/ipc/Cargo.toml`, `crates/ipc/src/lib.rs`, `crates/ipc/src/security.rs`
- Test: `crates/ipc/tests/pipe.rs`

**Interfaces:**
- Produces:
  - `pub fn pipe_name() -> String`: `WRAITH_PIPE_NAME` if set, else `\\.\pipe\wraith-<current user SID string>`
  - `pub struct PipeListener`, `PipeListener::bind(name: &str) -> io::Result<PipeListener>` (the first instance uses `FILE_FLAG_FIRST_PIPE_INSTANCE`, so a second server fails with `ErrorKind::AddrInUse`), `PipeListener::accept(&mut self) -> io::Result<PipeConn>` (blocks; creates the next instance before returning, so no connect window is missed)
  - `pub fn connect(name: &str) -> io::Result<PipeConn>`: `ErrorKind::NotFound` when no server is listening, `PermissionDenied` when the server process isn't owned by the current user
  - `pub struct PipeConn` (`Send`), `PipeConn::split(self) -> (PipeReader, PipeWriter)`. Both are `Send`, implement `Read` / `Write`, and work concurrently on one handle (overlapped I/O, one event per direction). Dropping both closes the handle.
  - `security::current_user_sid() -> String`, `security::pipe_sddl() -> String` (`D:P(A;;GA;;;<SID>)`), `security::process_owner_sid(pid: u32) -> io::Result<String>`

All handles are created with `FILE_FLAG_OVERLAPPED`. A read or write issues the operation with its own `OVERLAPPED` and event, then `GetOverlappedResult(..., wait = TRUE)`. Byte-mode pipe; framing comes from Task 1. A broken pipe or `ERROR_PIPE_NOT_CONNECTED` is reported as `Ok(0)` for reads and `BrokenPipe` for writes.

  - `connect_without_server_is_not_found`
  - `second_listener_is_addr_in_use`
  - `peer_drop_reads_eof` (drop the client; the server read returns `Ok(0)`)
  - `sddl_names_only_current_user` (contains the SID once, no `WD`/`AU`/`BU`)
  - `client_checks_server_owner` (`process_owner_sid(std::process::id())` == `current_user_sid()`)

### Task 3: Server session: registry, routing, attach/detach

**Files:**
- Create: `crates/server/src/session.rs`
- Modify: `crates/server/src/lib.rs`, `crates/server/Cargo.toml` (+`wraith-ipc`)
- Test: `crates/server/tests/session.rs`

**Interfaces:**
- Consumes: `spawn_pane`/`PaneHandle` (M1), `wraith_proto::wire::*`, `wraith_ipc::*`.
- Produces:
  - `pub fn run_server(pipe: &str) -> io::Result<()>`: blocks until `ServerStop`. Returns `AddrInUse` if another server owns the pipe.
  - `pub fn spawn_server_thread(pipe: &str) -> std::thread::JoinHandle<io::Result<()>>` (tests)
  - A test client helper lives in the test file, not in the lib.

Threads (spec §3.3):
- **Accept thread:** `PipeListener::accept` loop. Each connection gets a reader thread (`read_frame` → server channel) and a writer thread (bounded channel of 256 `ServerMsg`s → `write_frame`).
- **Main loop:** owns `HashMap<PaneId, Entry { handle: PaneHandle, client: Option<ClientId>, detached_at: Option<Instant>, title: String, exited: Option<u32> }>`.
- **Per-pane forwarder thread:** reads `PaneHandle.events` and forwards `(PaneId, PaneEvent)` to the main loop.

Rules:
- `Hello` with a different `proto_version` → `VersionMismatch`, then close.
- `Attach` takes the entry with the newest `detached_at` and no client (→ `reattached: true`: replay the cached `Title`, then `Exited` if exited, then send `PaneCmd::Reattach` plus `Resize` from `spawn`). Otherwise spawn from `spawn` (→ `reattached: false`).
- `Cmd` is accepted only for a pane attached to this client.
- Events for a pane with no attached client are dropped, except `Title`/`Exited`, which update the cache. The pane stops producing frames naturally: its credit is never acked.
- A client disconnect (reader EOF or writer error) detaches its panes (`detached_at = now`).
- If a client's writer queue is full, that client is too slow or dead: drop the client (detach its panes). The main loop never blocks on a client.
- `Kill` drops the `PaneHandle` (pane thread shutdown → Job Object kill) and removes the entry.
- `List` → `Panes`.
- `ServerStop` drops every pane and returns from `run_server`.

### Task 4: Client: `RemotePane`, connect-or-spawn, `--server` mode

- Test: `crates/client/tests/remote.rs`

**Interfaces:**
- Consumes: Tasks 1–3.
- Produces:
  - `pub struct RemotePane { pub id: PaneId, pub reattached: bool, pub events: Receiver<PaneEvent>, .. }`
  - `RemotePane::attach(pipe: &str, spawn: SpawnOpts, server_exe: &Path) -> Result<RemotePane, AttachError>`: connect → on `NotFound`, spawn `server_exe --server` and retry every 50 ms for 2 s → `Hello` → `Attach`
  - `RemotePane::send(&self, cmd: PaneCmd) -> Result<(), PaneCmd>`, `detach(self)`, `kill(self)`
  - `pub enum AttachError { NoServer { log_dir: PathBuf }, VersionMismatch { server_version: String }, Denied, Io(io::Error) }`
  - `pub fn spawn_server(exe: &Path) -> io::Result<()>`: `DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP | CREATE_BREAKAWAY_FROM_JOB`, retried without breakaway if that's denied. The server must outlive the client and any job the client is in.
  - In `main.rs`: `wraith.exe --server` → server logging → `run_server(&pipe_name())`. `AddrInUse` exits 0 (another server won the race).

Changes in `app.rs`:
- `pane: PaneHandle` → `pane: RemotePane` (same `send` / `events` use).
- On `reattached`, the window title comes from the replayed `Title`.
- `WinMsg::Close` → `detach` + `DestroyWindow`, with no confirmation (the shell keeps running).
- `close_surface` → confirm if running → `kill` + `DestroyWindow`.
- `AttachError` → a message box with the reason and the log path. `VersionMismatch` offers "Restart server (running shells will close)": `ServerStop`, then a new attach.
