# Wraith M7 — Spec Gaps Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the six spec features that are still missing, then bring the spec text up to date with what was built.

**Scope (from the 2026-11-02 spec review):**
- `wr config check`
- `wr events --json`
- a Retry choice when the server won't start
- the right-click menu
- inline IME composition
- `agent-tab-pulse`
- the spec refresh

Out of scope: the backlog items (quake window, settings GUI, auto-update, ARM64), Unicode-placeholder images, DirectComposition, and the deferred minors from earlier milestones.

**Architecture:** Each feature is a small pure function with tests, plus a thin Win32 or pipe hookup. `wr events` adds one message (`ClientMsg::Watch`): the server then sends that CLI client every model snapshot, and `wr` turns successive snapshots into JSON event lines. Nothing changes on the per-keystroke path.

**Tech Stack:** Rust (stable, MSVC), `windows` crate, serde/postcard, serde_json (already a `cli` dependency).

**Spec:** `docs/superpowers/specs/2026-11-01-wraith-terminal-design.md`. Sections covered:
- §3.1 `wr events --json`
- §5.4 `agent-tab-pulse`
- §6.2 IME preedit and the right-click menu
- §7 `wr config check`
- §8 server-not-running Retry

## Global Constraints

- Windows 10 1809+ / 11, x64. Rust stable, MSVC.
- CI must stay green: `cargo test --workspace` and `cargo clippy --workspace --all-targets -- -D warnings`.
- `PROTO_VERSION` goes from 3 to 4 (Task 2). Bump it once, in Task 2 only.
- §6.3 always fast: nothing added to the keystroke or frame path may walk scrollback or block on the pipe.
- §5.5: agent and hook text is untrusted. Text that `wr events` prints is JSON-escaped by serde_json; never print it raw.
- `wr` exit codes (`crates/cli/src/main.rs` header): 0 ok; 1 for a usage error, server error, unknown pane or bad config; 2 when no server is running. `wr` never starts a server.
- Live checks:
  - Use only a private pipe (`WRAITH_PIPE_NAME` = a full `\\.\pipe\...` name), `WRAITH_LAYOUT_PATH`, a fake `APPDATA`/`LOCALAPPDATA`, and windows shown without activation.
  - Never steal focus or send global input. Stop only processes you started, by PID.
  - Don't touch `target\release` (the user's own Wraith runs from it). Build release binaries with `--target-dir target/m7-release`.
  - Never edit the user's real `~/.claude/settings.json`, never change Windows settings, and never run a real install.
- Evidence: run `rtk proxy cargo test ...` and read the exit code. RTK condenses cargo output, so never grep its summary.

## Review Focus

1. **`wr events` when the server goes away mid-stream.** `wr` exits 0 promptly and never hangs. Test: `events_exit_when_server_stops` (Task 2).
2. **`wr config check` on a missing config file.** It counts as defaults, so exit 0. An unreadable file or a bad line in a `config-file` include gives exit 1 and prints `file:line`. Tests: `config_check_missing_file_is_ok`, `config_check_reports_include_errors` (Task 1).
3. **Right-click while the program has mouse tracking on** (vim, htop). The click goes to the program and no menu opens. This is a branch-order rule in Task 4: the tracking branch is checked first. Verify it live in acceptance.
4. **IME composition with the cursor near the right edge, or hidden.** The text shifts left to stay inside the pane. With no cursor it is placed at the pane's bottom-left. Focus loss or the end of composition clears it. Tests: `preedit_shifts_left_at_the_edge`, `preedit_without_cursor_sits_bottom_left`, `ime_end_clears_preedit` (Task 5).
5. **`agent-tab-pulse` with "Show animations" off.** The tab shows a steady tint with no redraw loop, so idle CPU stays at 0. Tests: `breathe_is_steady_when_animations_off`, `frame_interval_none_when_nothing_moves` (Task 6).

### Task 2: `wr events --json`

**Files:**
- Modify: `crates/proto/src/wire.rs` (add `ClientMsg::Watch`; `PROTO_VERSION = 4`)
- Modify: `crates/proto/tests/wire.rs` (round-trip `Watch`)
- Modify: `crates/server/src/session.rs` (`Client.watch: bool`; `Watch` handling; `push_snapshot` also sends to watchers)
- Create: `crates/cli/src/events.rs`
- Modify: `crates/cli/src/main.rs`
- Test: `crates/cli/tests/events.rs` (pure diff) and `crates/cli/tests/cli.rs` (end to end)

**Interfaces:**
- Produces:
  - `ClientMsg::Watch`. Only `ClientKind::Cli` may send it; any other kind is ignored. On `Watch`, the server sets `watch = true` and sends a `Snapshot` at once. After that, every `push_snapshot` also goes to watchers.
  - `pub fn diff(old: &ModelSnapshot, new: &ModelSnapshot) -> Vec<serde_json::Value>` in `crates/cli/src/events.rs`. It emits events in this order:
    1. Workspaces: `{"event":"workspace_opened","workspace":id,"name":..}`, `{"event":"workspace_closed","workspace":id}`, `{"event":"workspace_renamed","workspace":id,"name":..}`.
    2. Panes: `{"event":"pane_opened","pane":id,"workspace":ws,"title":..,"cwd":..}`, `{"event":"pane_closed","pane":id}`, `{"event":"title","pane":id,"title":..}`, `{"event":"cwd","pane":id,"cwd":..}`, `{"event":"exited","pane":id,"code":n}`.
    3. Agents: `{"event":"agent","pane":id,"harness":..,"state":"idle"|"working"|"asking"|"done"|null,"attention":bool,"message":..}`. This event fires when `agent`'s `harness`, `state`, `attention` or `message` changes. `null` means detached.
  - Each pane's workspace comes from the tab whose `root.contains(pane)`.
- Ruling: `wr events` with or without `--json` prints JSON lines. The spec names only `--json`, and a second plain-text format would be code nobody asked for.

- [ ] **Step 1: Write the failing tests.**
  - `crates/proto/tests/wire.rs`: `rt(ClientMsg::Watch)`.
  - `crates/cli/tests/events.rs`, on hand-built snapshots:
    - `first_snapshot_reports_everything_opened`: diff against `ModelSnapshot::default()`.
    - `title_change_is_one_event`.
    - `agent_ask_then_detach`: `state` goes `"asking"`, `attention` true, then `state` null.
    - `closed_pane_and_workspace`.
    - `unchanged_snapshot_is_silent`: diff of a snapshot with itself is empty.
  - `crates/cli/tests/cli.rs`:
    - `events_stream_pane_opened_and_exit`: start `wr events --json` with piped stdout, then open a pane with the `gui` helper. A line with `"event":"pane_opened"` for that pane arrives within 5 s.
    - `events_exit_when_server_stops`: `wr ctl server-stop`, then `wr events` exits with status 0 within 5 s.
    - `events_no_server_exits_2`.
- [ ] **Step 2: Run them.** `rtk proxy cargo test -p wraith-proto -p wraith-cli` → FAIL (`Watch` unknown, `events` module missing).
- [ ] **Step 3: Implement.**
  - Bump `PROTO_VERSION` to 4.
  - Server: in `client_msg` (`session.rs:436`), `ClientMsg::Watch` with `kind == Some(Cli)` sets `watch` and sends `Snapshot(self.model.snapshot())`. Change `push_snapshot` to send to `gui_ids()` plus watchers. The existing `try_send` drop rule covers slow readers.
  - `wr`: `["events"] | ["events", "--json"]`:
    1. Open a `session()` and send `Watch`.
    2. Loop on `read_frame`. On each `Snapshot`, print `diff(&last, &snap)` as one compact JSON line per event and flush stdout.
    3. When the pipe read fails, return `Ok(())` (the server went away: exit 0).
    4. A stdout write error (reader closed) also returns `Ok(())`.
- [ ] **Step 4: Run.** `rtk proxy cargo test --workspace` → exit 0. The client and server tests still pass on version 4.

### Task 3: Retry when the server won't start (§8)

**Files:**
- Modify: `crates/client/src/link.rs` (add `retry_attach`)
- Modify: `crates/client/src/app.rs:1540-1571` (`attach_with_restart` uses it)
- Test: `crates/client/tests/link.rs`

**Interfaces:**
- Produces: `pub fn retry_attach<L>(connect: impl FnMut() -> Result<L, AttachError>, retry: impl FnMut(&AttachError) -> bool) -> Result<L, AttachError>`.
  - It calls `connect`. On `Err(e)` where `e` is not `VersionMismatch`, it asks `retry(&e)` and loops while that returns true.
  - It returns the first `Ok`, the `VersionMismatch` error unchanged, or the last error when `retry` declines.
- Ruling: the spec's "error screen" is a Retry/Cancel message box carrying the error text, which already includes the log folder (`AttachError::NoServer`'s `Display`). The window has nothing to draw until it attaches, and a custom screen would add a render path used only for this one case. Cost if wrong: a dialog where a drawn screen was wanted. The behaviour is the same.

  - `retry_attach_cancel_returns_error`: `retry` answers false. Result is `Err(NoServer)`, after 1 connect.
  - `retry_attach_leaves_version_mismatch_to_the_caller`: `connect` returns `VersionMismatch`. `retry` is never called.

  - The reconnect after a restart also goes through `retry_attach`.

### Task 6: `agent-tab-pulse` (§5.4)

**Files:**
- Modify: `crates/config/src/lib.rs`, `crates/config/src/keys.rs` (`agent_tab_pulse: bool`, default false)
- Modify: `crates/client/src/motion.rs` (`breathe`, `set_breathing`, `frame_interval`)
- Modify: `crates/client/src/app.rs` (tab wash; the idle loop uses `frame_interval`)
- Test: `crates/config/tests/parse.rs`, `crates/client/tests/motion.rs`

**Interfaces:**
- Produces:
  - `pub const BREATHE: Duration = Duration::from_millis(1600)`.
  - `Motion::set_breathing(&mut self, on: bool, now: Instant)`. It records the start time when breathing turns on.
  - `Motion::breathe(&self, now) -> f32`:
    - 0 when not breathing.
    - A steady 0.5 when breathing with animations off.
    - Otherwise `0.5 - 0.5 * cos(2π · t / BREATHE)`.
  - `Motion::frame_interval(&self, now) -> Option<Duration>`: `Some(16 ms)` when `active(now)`; else `Some(50 ms)` when breathing with animations on; else `None`.
  - `active` is unchanged, so existing tests keep their meaning.
- Ruling: breathing redraws at 20 Hz (every 50 ms), not 60. The wave lasts 1.6 s, so 20 Hz looks smooth, and it costs a third of the frames while an agent waits. Cost if wrong: a slightly steppier pulse.
- Ruling: the pulse is a wash of the accent over the tab background, `mix(bar_bg, accent, 0.25 * breathe)`, on tabs whose agent has attention. The spec says only "optional pulse".

    - `breathe_is_steady_when_animations_off`: `Motion::new(false)` gives 0.5 at any time, and `frame_interval == None`.
    - `breathing_stops_when_attention_clears`: after `set_breathing(false)`, `breathe` is 0.
    - `frame_interval_slows_for_breathing_only`: breathing alone gives 50 ms; breathing plus an active slide gives 16 ms.
    - `frame_interval_none_when_nothing_moves`.
- [ ] **Step 2: Run them.** `rtk proxy cargo test -p wraith-config -p wraith-client` → FAIL.

  - Replace the idle-loop check `if self.motion.active(now) { dirty; sleep = min(16) }` with `if let Some(d) = self.motion.frame_interval(now) { dirty; sleep = min(d) }`.
  - Hot reload: `reload.rs` already re-reads `Config`, so make sure the flag is read from `self.config` each frame.
