# Wraith M6 — Hover Feedback and Polish

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Make the window feel mouse-friendly and alive.
- Every clickable piece of chrome reacts to hover and press.
- The pointer shape says what a press will do.
- State changes move briefly instead of jumping.
- Buttons say what they do and which key does it.

None of this may cost input latency.

**Scope (user's choice, 2026-11-02):** the backlog's hover feedback and polish ("juice") pass. Out of scope: the quake window, the settings GUI, auto-update, ARM64.

**Spec:** `docs/superpowers/specs/2026-11-01-wraith-terminal-design.md`. This plan implements the §10 Backlog row (hover feedback, polish pass), §4.2 (window layout) and §6.3 (always fast).

**Architecture:**
- **What is under the pointer and what is pressed:** state in `WindowView`, with no window or GPU, so it is tested directly like the rest of the view.
- **Motion:** time-based values in a new pure module, `crates/client/src/motion.rs`. `App::render` evaluates them at draw time. A change of target restarts the motion from wherever it is now.
- **Pointer shape and tooltip text:** pure functions in `chrome.rs`. `app.rs` only applies them.

**Tech stack:** Rust, `windows` crate (`WM_SETCURSOR`, `SetCursor`, `SystemParametersInfoW(SPI_GETCLIENTAREAANIMATION)`), the existing D3D11 quad pipeline (`Painter` alpha does the fades).

## Global Constraints

- **Latency (spec §6.3):** animation never costs input latency.
  - Animation frames go through `try_render(false)` only, never a blocking wait.
  - Input messages are handled before any frame is drawn, exactly as today.
  - An animation is a function of time evaluated at render. It does no work between frames.
- **Idle stays idle:** when nothing animates, the loop sleeps as it does today. There is no redraw per pointer move. Hover redraws only when the target under the pointer changes.
- **Panes never animate size:** docking or undocking the sidebar, splits and zoom stay instant. Animating them would resize the shells on every frame.
- **Durations:** hover fade 80 ms. Slides and overlay entrances 120 ms. Attention-dot pulse 600 ms, played once when the dot appears. Ease-out cubic.
- **Reduced motion:** when Windows "Show animations" is off (`SPI_GETCLIENTAREAANIMATION` is false), every motion completes at once. The setting is read at startup and on `WM_SETTINGCHANGE`.
- **Colors:** derived from the theme through `chrome::mix`, like all chrome (spec §4.2). There are no fixed colors except the caption close button's red, which already exists.
  - hover wash `mix(bar_bg, bar_fg, 0.08)`
  - press wash `mix(bar_bg, bar_fg, 0.16)`

## Rulings at planning

- **No config key for animations.** The Windows setting is the switch; it also covers Remote Desktop, which turns it off. *Cost if wrong:* one config key added later.
- **The pointer shape follows the target.**
  - Arrow over chrome. The tab bar's empty area is non-client and Windows handles it.
  - A resize arrow over a divider: `IDC_SIZEWE` for a vertical line, `IDC_SIZENS` for a horizontal one.
  - I-beam over a pane, or arrow when the pane has mouse tracking on and the program owns the mouse.
  - No hand cursor. Windows chrome does not use one.
- **Press feedback lasts while the button is held.** Clicks still act on press, as today, so a quick click flashes for about one frame. A held press on a tab (the start of a drag) shows it.
- **Tooltips only on icon-only buttons:** `+` (new tab), `×` (close tab), `+ New workspace`, and the caption buttons. Rows that show their own text get none.
  - A tooltip appears after the pointer rests on a button for 500 ms.
  - It shows the action's name and its current binding from config, so a rebind shows up.
  - Drawn by Wraith with theme colors, not a Win32 tooltip window.
- **The palette takes the mouse.**
  - Hovering a row selects it, a click runs it, and the wheel scrolls it.
  - A click outside the palette closes it.
  - A click outside the find bar leaves it open (search is often used while reading the pane).

## Review Focus

1. **The pointer moves all over a pane while it floods output:** no extra redraws, because the hover target (`Hit::Pane(p)`) does not change. Test: `hover_reports_only_target_changes`.
2. **The hovered tab or workspace disappears** (another window closes it, or a snapshot removes it): no stale highlight and no panic. Hover is recomputed on every snapshot. Test: `hover_drops_target_that_disappears`.
3. **Capture is lost mid-press** (Alt+Tab, a modal box): the press highlight clears. `WM_CAPTURECHANGED` and `WM_KILLFOCUS` reset `pressed`. Test: `capture_lost_clears_press`.
4. **The DPI or window size changes mid-slide:** the slide jumps to its new target and does not glide from coordinates in the old scale. Test: `snap_jumps_without_motion`.
5. **"Show animations" is off:** no animation frames are scheduled, and every change is instant. Test: `reduced_motion_completes_at_once`; the idle check is in acceptance.

### Task 3: Motion

**Files:**
- Create: `crates/client/src/motion.rs`, exported from `lib.rs`
- Modify: `crates/client/src/app.rs`
  - a `Motion` field holding the slides and fades below
  - `render` retargets them and draws with their current values
  - `idle` keeps the frame-latency wait (`wait_on`) while anything animates, and sleeps as before once nothing does
- Modify: `crates/client/src/window.rs`: read `SPI_GETCLIENTAREAANIMATION` at startup and on `WM_SETTINGCHANGE`.
- Test: `crates/client/tests/motion.rs`

**Interfaces (`motion.rs`):**
- `pub fn ease_out(t: f32) -> f32`: cubic; `t` is clamped to 0..=1.
- `pub struct Slide`: an animated `Rect`.
  - `new(r: Rect)`
  - `retarget(&mut self, to: Rect, now: Instant, dur: Duration)`: starts from the current value. A target equal to the current one changes nothing.
  - `snap(&mut self, to: Rect)`
  - `value(&self, now: Instant) -> Rect`
  - `active(&self, now: Instant) -> bool`
- `pub struct Fade`: an animated `f32` between 0 and 1.
  - `set(&mut self, on: bool, now: Instant, dur: Duration)`
  - `value(&self, now: Instant) -> f32`
  - `active(&self, now: Instant) -> bool`
- `pub struct Pulse`: plays once from `start`. `value(now)` rises 0→1→0 over the duration, then stays 0.
- `pub fn duration(base: Duration, animations_on: bool) -> Duration`: `ZERO` when animations are off.

**What moves:**

| Element | Motion | Duration |
|---|---|---|
| Active tab underline | Slides from the old tab to the new one. The tab background itself switches at once. | 120 ms |
| Sidebar current-workspace accent bar (2 px) | Slides between rows | 120 ms |
| Floating sidebar | Slides in from the left edge on reveal and out on hide. The docked toggle stays instant. | 120 ms |
| Palette and find bar | Fade in, rising from 8 px below. Closing is instant: Esc must feel immediate. | 120 ms |
| Hover and press washes | Fade in and out. One `Fade` per `Hit`, kept in a `HashMap<Hit, Fade>` and pruned when it reaches 0. | 80 ms |
| Attention dot (tab badge, workspace row, agent row) | Pulses once when it appears (`Pulse` on the false→true edge). The working spinner is unchanged. | 600 ms |
| Notices (toast) | Fade in | 120 ms |

`set_geometry`, a DPI change and a workspace switch call `snap` on every slide. Review Focus 4 covers this.
