# Wraith M0 + M1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prove libghostty-vt and ConPTY work on Windows (M0), then ship a single-window, single-pane terminal you can use daily (M1).

**Architecture:** One Cargo workspace. The pane engine (ConPTY + libghostty `Terminal` on its own thread, emitting `FrameDelta`s) lives in the `wraith-server` library from day one. In M1 the GUI client links it directly and talks to it over in-process channels. In M2 the channels become the named pipe without changing the pane engine. The client is raw Win32 + D3D11 + DirectWrite through the `windows` crate.

**Tech Stack:** Rust stable (MSVC), Zig 0.17.x, `libghostty-vt = "=0.2.2"`, `windows` crate, `serde` + `postcard`, `crossbeam-channel`, `notify`, `tracing` + `tracing-appender`.

**Spec:** `docs/superpowers/specs/2026-11-01-wraith-terminal-design.md` (§3.2, §3.3, §3.4 cell encoding + backpressure, §6, §7, §8, §10 M0/M1, §11)

## Global Constraints

- Target `x86_64-pc-windows-msvc`. Minimum OS Windows 10 1809 (ConPTY).
- Zig **0.17.x** on PATH (or `ZIG` env var). The dev machine has 0.16.0 and must upgrade first.
- `libghostty-vt` pinned `=0.2.2`. Imported **only** by `wraith-server` (and its tests).
- Keypress-to-pixel latency target: **< 8 ms at 120 Hz**.
- Config path `%APPDATA%\wraith\config`. Logs `%LOCALAPPDATA%\wraith\logs\{client}-YYYYMMDD.log`, 7-day retention, level from `WRAITH_LOG`.
- Config uses Ghostty key names and `key = value` syntax wherever the meaning overlaps.
- A pane is **never resized below 2×1 cells**.
- Every test that needs Windows APIs is `#[cfg(windows)]`. CI runs `cargo test --workspace` and `cargo clippy --workspace -- -D warnings` on `windows-latest`.
- Defaults chosen by this plan: `font-family = Cascadia Mono`, `font-size = 12`, `scrollback-limit = 10000000` (bytes, Ghostty semantics), `command` = `pwsh.exe` if found on PATH, else `powershell.exe`.

## Review Focus

1. **Output floods** (`type` of a 100 MB file, `yes`): the window stays responsive and memory stays flat. Task 7 `flood_coalesces_to_one_pending_frame`.
2. **Minimize and zero-size windows:** a minimized window reports a 0×0 client rect, and the pane must not be resized to 0×0. Task 12 `zero_client_rect_does_not_resize`.
3. **Moving the window between monitors with different DPI:** cell metrics and the atlas rebuild at the new DPI. Task 9 `metrics_scale_with_dpi`.
4. **Non-US keyboard layouts:** AltGr+Q on German produces `@` as text, not Ctrl+Alt+Q. Task 11 `altgr_produces_text_not_ctrl_alt`.
5. **Config files saved by Notepad** (UTF-8 BOM, CRLF line endings): they parse the same as LF/no-BOM. Task 5 `bom_and_crlf_are_ignored`.

  - Wheel input arrives as `PaneCmd::Mouse` with `MouseButton::Wheel*`. The pane decides: mouse tracking on → encode it; alternate screen on → send arrow keys (3 per notch); otherwise scroll the viewport 3 rows per notch.
  - `pub enum ScrollTo { Delta(i32), PageUp, PageDown, Top, Bottom }`, `pub struct SelRange { pub start: (u16,u16), pub end: (u16,u16), pub rectangle: bool }` (viewport coordinates)

Thread layout (spec §3.3): a reader thread does blocking reads into 64 KiB chunks and sends them to the pane thread. The pane thread `select!`s on chunks and `PaneCmd`s.

Backpressure: keep `outstanding: bool`. After any `vt_write` or command that dirties the screen, if `!outstanding`, build a frame, send it, and set `outstanding = true`. `Ready(seq)` clears it and, if the screen is dirty again, sends the next frame right away. Dirty rows are merged in a local `BTreeSet<u16>` while a frame is outstanding, so nothing is lost. The first frame and every frame after `Resize`/`SetColors` are `full`.

`Paste`: run libghostty-vt's paste-safety check. Unsafe or multi-line text → `PasteNeedsConfirm(text)`, and nothing is written. The client re-sends it as `Text` after the user confirms. Safe text is written with bracketed-paste wrapping when mode 2004 is on.

On child exit, emit `Exited(code)`. `Restart` respawns the `Pty` with the same options and resets the `Terminal`.
