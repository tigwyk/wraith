# Wraith M5 — Scrollback Search, Scrollback Persistence, Local Packaging

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:**
- Find text in a pane's history.
- Keep each pane's history across a server restart.
- Ship Wraith as a per-user zip, with an install script and a local winget manifest. Nothing is published.

**Scope (user's choice, 2026-11-02):** scrollback search, scrollback persistence, local-only packaging. Out of scope: the quake window, the settings GUI, auto-update, ARM64.

**Spec:** `docs/superpowers/specs/2026-11-01-wraith-terminal-design.md` (§10 M5 row; §2 non-goal "persisting scrollback across a server restart" is lifted by this milestone).

## Global Constraints

- **Speed:** search work never blocks input. A pane thread does at most a bounded slice of search per frame, so the 2 ms input rule (spec §6.3) holds while searching a full scrollback.
- **Search UI:** `ctrl+shift+f` opens find on the focused pane. Typing searches as you type. Enter goes to the next (older) match, Shift+Enter to the previous, Esc closes and clears.
  - Matches are highlighted in the viewport, the selected one stronger.
  - A count shows `n/total`.
  - Matching is libghostty's: byte-exact, ASCII case-insensitive.
- **Saving history:** only on `server-stop` (the server is the process that owns it), next to `layout.json` in `scrollback/<pane>.snap`.
  - Files are written atomically (temp file, then rename).
  - A pane gets at most 2 s in total; panes not done by then are skipped, not waited on.
- **Restoring history:** a restored pane starts with its old history above a dim marker line: `── restored <date time> ──`.
  - The old screen is pushed into scrollback, and the alternate screen and modes are reset first, so a restored `vim` screen does not linger.
  - Snapshot files are deleted once loaded.
  - A snapshot that fails to decode (the format is "work in progress" upstream) gives a fresh pane and a log line, never an error the user must handle.
- **Packaging:** per-user, no admin. Installed to `%LOCALAPPDATA%\Programs\Wraith`, with `wr.exe` added to the user `PATH`, and a Start Menu shortcut plus an uninstall entry under HKCU. The zip contains `wraith.exe`, `wr.exe`, `OpenConsole.exe`, `conpty.dll`, `themes/` and `LICENSE`.

## Rulings at planning

- **Highlights travel with the frame.** Search highlights are computed on the pane thread and sent in `FrameDelta.search`: the viewport's matches as cell ranges, plus the count and selected index. The client only draws them.
- **No periodic history save.** History is saved on `server-stop` only. A crash or logoff keeps the layout (saved continuously) but not the history. *Cost:* history lost on a crash.
- **winget manifest:**
  - type `zip` with nested `portable` entries for `wraith.exe` and `wr.exe`, version 0.1.0;
  - `InstallerUrl` points at a placeholder release URL, because there is no host yet;
  - validated with `winget validate`, never submitted.

## Review Focus

1. **Search during a flood:** a pane flooding output while a search is open still answers input within 2 ms. Matches catch up; they never stall.
2. **Huge scrollback:** search over a full scrollback (10k+ lines) stays responsive, and the count grows while it runs.
3. **A snapshot from another Ghostty version, or a corrupt one:** decodes to a fresh pane and the file is removed. The server never crashes or loops.
4. **A pane's snapshot exists but the pane is not in the layout:** stale files are deleted at startup.
5. **Install over an existing install, or while Wraith runs:** the script refuses while `wraith.exe` from the install folder is running, and otherwise replaces the files.

### Task 1: Scrollback search

**Files:** `crates/proto/src/{pane.rs,frame.rs}`, `crates/server/src/{pane.rs,search.rs}`, `crates/config` (`find` action + default `ctrl+shift+f`), `crates/client/src/{view.rs,app.rs,grid.rs}`.

**Interfaces:**
- `PaneCmd::Search(SearchCmd)` with `SearchCmd { Set(String), Next, Prev, Close }`.
- `FrameDelta.search: Option<SearchView { total: u32, selected: Option<u32>, hits: Vec<SearchHit { y: u16, x0: u16, x1: u16, selected: bool }> }>`.
- Server `search.rs`: `fn hits(term, search, buf) -> SearchView`, splitting wrapped matches per row.
- Client: a `Find` state in the view, `find_key(&KeyEvent) -> Option<Out>` (like `palette_key`), and a small find bar at the top right of the focused pane.

**Tests:**
- server `search_finds_and_highlights_viewport_matches`, `next_scrolls_to_older_match`, `close_clears_highlights`, `search_keeps_input_fast_while_flooding`;
- client view `find_keys_drive_search_cmds`, `esc_closes_find_and_clears`.

### Task 2: Scrollback persistence

**Files:** `crates/server/src/{session.rs,pane.rs,model.rs}`, `crates/proto/src/pane.rs` (server-internal command), `crates/server/tests/session.rs`.

**Interfaces:**
- **Save:** `PaneCmd::SaveScrollback(String)`, accepted only from the server itself (clients' copies are dropped, like `Shutdown`), answered with `PaneEvent::ScrollbackSaved`.
- **Restore:** `PaneOptions.restore: Option<PathBuf>`.
- **Stop:** `server-stop` saves layout and history before dropping panes.
- **Startup:** stale `.snap` files are removed.

**Tests:**
- session `server_stop_saves_and_restart_restores_history` (a pane prints a unique marker; stop; restart from the same layout; the restored pane's frames contain the marker in history and a fresh prompt below);
- `corrupt_snapshot_gives_fresh_pane`;
- `stale_snapshots_are_removed`;
- `clients_cannot_send_save_scrollback`.

### Task 3: Local packaging

**Files:**
- `scripts/dist.ps1` (build the release, assemble `dist/wraith-<ver>-x64.zip`, print the SHA256);
- `packaging/install.ps1` and `packaging/uninstall.ps1`;
- `packaging/winget/` manifests (version 0.1.0).

**Checks:**
- `dist.ps1` produces the zip with the listed files;
- `install.ps1` installs into a temp `-Prefix` in a test run, with no PATH, Start Menu or registry changes under `-DryRun`;
- `winget validate` passes on the manifests.
