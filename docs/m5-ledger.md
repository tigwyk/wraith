# M5 ledger — plan: docs/superpowers/plans/2026-11-02-wraith-m5.md

Plan: Ruling: scope from the user (search, persistence, local packaging); highlights computed on the pane thread and sent in FrameDelta.search; history saved on server-stop only; winget zip+portable manifest, validated, not submitted.
Task 1: complete — scrollback search: PaneCmd::Search(Set/Next/Prev/Close); server search.rs on libghostty's incremental Search (64 ticks per frame, keeps frames coming while running); FrameDelta.search {total, selected, per-row hits (wrapped matches split)}; client `find` action (ctrl+shift+f, palette group Panes), find bar (type to search, Enter older, Shift+Enter newer, Esc closes) at the searched pane's top right with n/total; grid draws hit/selected backgrounds. server pane +4 (incl. flood p99 < 2 ms with a search open), view +3, grid +1; workspace + clippy green.
Task 1: Ruling: while the find bar is open it takes every key (like the palette), so pane keybinds pause until Esc — cost if wrong: a user expecting e.g. ctrl+tab to work inside find.
Task 2: complete — scrollback persistence: server-stop sends PaneCmd::SaveScrollback(<layout dir>/scrollback/<pane>.snap) to every pane and waits ≤ 2 s total for ScrollbackSaved (libghostty encode_snapshot, temp file + rename); a restored pane decodes its file (deleted either way), leaves the alternate screen, soft-resets, writes a dim "── restored <time> ──" line right after the old output and scrolls it all into history; undecodable files give a fresh pane; stale .snap files removed at startup; clients' SaveScrollback dropped. session +4 (history restored above the marker, corrupt, stale, clients refused); workspace + clippy green.
Task 2: Bug found by its own test: the restore sequence ran only when the snapshot had scrollback rows, so a one-screen history was never restored; it now runs whenever a snapshot decoded. The test was also strengthened: the restored pane re-runs its command, so the old output must appear *above* the marker line.
Task 2: Ruling: the marker is written where the old cursor was (after the last output), not at the bottom row, so history has no blank gap before it — cost if wrong: none.
Task 3: complete — packaging: scripts/dist.ps1 (Zig 0.17 check, release build, dist/wraith-<ver>-x64.zip with wraith/wr/OpenConsole/conpty, themes, install/uninstall scripts, notices; SHA256 written into the winget installer manifest); packaging/install.ps1 (per-user to %LOCALAPPDATA%\Programs\Wraith, refuses while that copy runs, user PATH, `wraith.exe --register` Start Menu shortcut with the AUMID, HKCU uninstall entry; -DryRun copies only), uninstall.ps1 (keeps settings/layout/logs); winget manifests (zip + portable wraith/wr, placeholder URL) pass `winget validate`. Checked: zip built (3.8 MB); dry-run install to a temp prefix (892 themes; PATH and registry unchanged); the installed copy runs with its own bundled OpenConsole; install refuses while it runs; refusals exit 1; --register writes a shortcut whose AUMID reads back as Wraith.Terminal.
Task 3: Ruling: `wraith.exe --register [<lnk>]` added so the installer can create the AUMID shortcut (PowerShell cannot set System.AppUserModel.ID) — cost: one more startup flag.
Task 3: Ruling: no LICENSE file is shipped: the repo has none (Cargo says MIT) and writing one names a copyright holder — the user's decision; THIRD-PARTY-NOTICES.txt + libghostty-rs's LICENSE ship instead.
Task 3: Not run: a real (non-dry) install/uninstall — it edits the user's PATH, Start Menu and registry; `winget install` — needs a hosted URL.
